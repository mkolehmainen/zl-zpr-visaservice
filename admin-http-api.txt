Admin HTTP API  - Current as of 9/22/2026
-----------------------------------------

This document describes the admin HTTPS API implemented by the server and
consumed by vs-admin. This API is under active development and changes
frequently.

Base URL
--------
  The default admin port for the visa service is 8182. So in a default visa
  service setup, the base url is "https://[fd5a:5052::1]:8182".

Transport
---------
  TLS required. The admin client uses a configured root certificate and also
  accepts invalid certs.

Content Type
------------
  All request and response bodies are JSON.

API KEY
-------
  Every request requires passing the api key in the `X-API-Key` header.
  A missing, malformed, or unknown key gets a 401 (not listed per endpoint).
  Keys carry one of four permission levels: resolve, read, read/write, or
  notify.
  GET /admin/services, GET /admin/services/{name} and GET /admin/hosts/{name}
  accept any active key except notify — a resolve key reaches exactly those
  three endpoints. All other read endpoints require read; write endpoints
  (POST/DELETE) require read/write, else 403.
  A notify key reaches exactly one endpoint: POST /admin/services/{id}/changed,
  and only for the single trusted-service id the key was bound to at mint
  time (vsapikey create notify <owner> --service <id>). Read/write keys may
  also call that endpoint, for any id.

Notes
-----
  - Some endpoints in admin_service still return placeholder or fixed data
    (the authrevoke endpoints, DELETE visas, and DELETE actors). These are
    marked "placeholder" below.
  - A few fields are hardcoded or not tracked yet; see endpoint notes.
  - All timestamps are integer seconds since the Unix epoch. Nullable
    timestamps serialize as JSON null.

Endpoints
---------
GET /admin/actors
-----------------
  Summary
    Returns a list of connected actors: ZPR address plus optional CN.
  Query
    role: node | adapter (optional; invalid value => 400)
  Request
    (none)
  Response
    200: ActorEntry[]
    400: invalid role query value
    403: permission denied (empty list)
    500: empty list

GET /admin/actors/{zpr_addr}
----------------------------
  Summary
    Returns details for the actor at the given ZPR address.
  Request
    (none)
  Response
    200: ActorDescriptor
    400: malformed ZPR address
    403: permission denied
    404: not found
    500: server error
  Notes
    created is currently 0 (actor create time not tracked yet).
    node_details is populated for node actors and null for adapters.
    cn is null for actors without a CN (e.g. an OIDC-only connect).
    hostname_conflicts lists the actor's refused device.hostname claims
    (first-claim-wins; see GET /admin/hosts/{name}). Empty in the normal case.

DELETE /admin/actors/{zpr_addr}
-------------------------------
  Summary
    Kicks the actor's live session (its credential is untouched;
    credential revocation is /admin/authrevoke). Placeholder: the
    address is validated but the response is fixed.
  Request
    (none)
  Response
    200: Revokes
    400: malformed ZPR address
    403: permission denied
    404: not found

GET /admin/actors/{zpr_addr}/visas
----------------------------------
  Summary
    Returns the IDs of all visas whose five-tuple has this actor's ZPR
    address as either the source or destination.
  Request
    (none)
  Response
    200: ListEntry[]
    400: malformed ZPR address (empty list)
    403: permission denied (empty list)
    404: actor not found (empty list)
    500: server error (empty list)
  Notes
    Currently scans every visa (O(n)); an index is pending a visa_mgr
    rework. No pagination support yet.

GET /admin/nodes/{zpr_addr}/visas
---------------------------------
  Summary
    Returns the IDs of the visas currently installed on the given node.
  Request
    (none)
  Response
    200: ListEntry[]
    400: malformed ZPR address, or actor is not a node (empty list)
    403: permission denied (empty list)
    404: actor not found (empty list)
    500: server error (empty list)
  Notes
    {zpr_addr} must resolve to a node actor; non-node actors return 400.

GET /admin/services/{name}
--------------------------
  Summary
    Returns details for a specific service by name.
  Request
    (none)
  Response
    200: ServiceDescriptor
    403: permission denied
    404: not found
    500: server error
  Notes
    Note that passed {name} must be url path encoded.
    service_kind and service_endpoints are sourced from the current policy
    (both "" if the service is not present in it).

DELETE /admin/services/{id}/cache
---------------------------------
  Summary
    Refreshes a trusted service's attribute data and reconciles the system against
    it. Use after the service's external data (e.g. its attribute file) changed.
  Request
    (none)
  Response
    202: accepted (reload succeeded, reconciliation queued)
    403: permission denied (read-only key)
    404: no such trusted service
    500: reload failed (e.g. the attribute file is missing or unparseable)
  Notes
    The reload is synchronous, so a 202 means the new data is live. The
    reconciliation that follows is asynchronous: the actors behind live visas are
    refreshed from the service and their visas re-checked against current policy,
    with visas no longer allowed queued for revocation. Its outcome is logged, not
    returned.
    Actors with no live visa are not touched here -- they refresh on their next
    visa request.
    Note that passed {id} must be url path encoded.

POST /admin/services/{id}/changed
---------------------------------
  Summary
    A trusted (attribute) service notifies the VS that its data changed
    (zipline#79). Rides the same flush -> revision -> reconcile -> revoke
    path as DELETE /admin/services/{id}/cache.
  Request
    {}                                        everything changed
    { "identities": [ { "<zpr key>": "<value>" }, ... ] }
                                              only the actors carrying a
                                              listed identity pair changed
  Response
    202: accepted (reconciliation queued)
    400: malformed body (non-JSON, unknown fields, or an empty identity
         object)
    403: permission denied (key without notify rights, or a notify key bound
         to a different service id)
    404: no such trusted service
    500: reload failed, or actor listing failed
  Notes
    Requires a notify or readwrite key. A notify key is bound to exactly one
    service id at mint time and gets 403 for any other id — checked BEFORE
    the existence check, so a bound key cannot probe which ids exist. A
    readwrite key may notify any id and sees the 404 for an unknown one.
    Body {} is equivalent to DELETE /admin/services/{id}/cache: the service
    is reloaded synchronously and the asynchronous reconciliation is queued
    (actors behind live visas refreshed, their visas re-checked).
    A targeted body does NOT reload the service (a service pushing a
    notification is assumed to vend current data). Instead, for every
    connected actor whose stored attributes contain a listed key=value pair
    exactly, the actor's recorded revision for this source is forgotten, so
    the queued reconciliation re-queries exactly those actors. Actors with no
    live visa refresh lazily on their next visa request.
    Note that passed {id} must be url path encoded.

GET /admin/hosts/{name}
-----------------------
  Summary
    Resolves a claimed hostname to the actor holding it (zipline#54).
  Request
    (none)
  Response
    200: HostDescriptor
    403: permission denied
    404: no such hostname (unclaimed, or never claimable)
    500: server error
  Notes
    Accepts any active key, including a resolve key — this endpoint sits on
    the resolve surface with the two service-resolution endpoints. A resolve
    key reaches exactly those three; in particular it cannot read actors, so
    resolving grants no actor visibility beyond the one name asked for. There
    is deliberately no GET /admin/hosts listing.
    Names enter the index via the device.hostname attribute claim
    (first-claim-wins per value; policy service names always win). The claim
    side stores the caller's value without transformation, and this lookup
    queries the same way — no mangling on either side — so the name must be
    spelled exactly as claimed: a single lowercase DNS label. An invalid label
    is simply never in the index and reports the same 404 as an unclaimed one.
    Refused claims are visible on the losing actor's ActorDescriptor
    hostname_conflicts field (read-gated).
    Note that passed {name} must be url path encoded.

GET /admin/visas
----------------
  Summary
    Returns a list of all visa IDs (u64).
  Request
    (none)
  Response
    200: ListEntry[]
    403: permission denied (empty list)
    500: empty list
  Notes
    No pagination support yet.

GET /admin/visas/{id}
---------------------
  Summary
    Returns details for a specific visa.
  Request
    (none)
  Response
    200: VisaDescriptor
    403: permission denied
    404: not found
    500: server error
  Notes
    expires and created are seconds since epoch.
    policy_id is the policy version the visa was issued under.
    proto is derived from the visa (TCP, UDP, ICMP, or N/A).
    For UDP/TCP, source_port/dest_port are ports; for ICMP they carry the
    ICMP type/code. All of source_addr, dest_addr, and the ports are null
    when the visa has no dock_pep.

GET /admin/visas/denies
-----------------------
  Summary
    Returns the recent visa denies, most recently denied first. Denies are
    collapsed on (source_addr, dest_addr, protocol, dest_port, deny_code), so a
    repeat of the same traffic bumps count rather than adding a row.
  Query
    since: number (optional; epoch MILLISECONDS, inclusive)
    limit: number (optional; max entries returned)
  Request
    (none)
  Response
    200: DenyRecord[]
    400: malformed query value (non-numeric or negative since/limit)
    403: permission denied (empty list)
  Notes
    last_deny_ms and since are epoch MILLISECONDS, unlike the seconds used by
    every other endpoint in this API.
    since is inclusive: an entry is returned when last_deny_ms >= since.
    The window holds at most DENY_LOG_SIZE (500) entries; recording a new key
    beyond that drops the least recently denied one. A repeat of an existing key
    moves it back to the newest end, so it survives eviction.
    The window is in memory only and starts empty after a visa service restart.
    Entries are ordered by deny recency, not by last_deny_ms. A system clock
    change can therefore leave timestamps out of order in the returned list.
    dest_port carries the ICMP code for ICMP traffic, per the visa request's
    five-tuple. source_port is not part of the key and is not reported.
    Only actual visa denials are recorded; internal errors and request timeouts
    are not.

DELETE /admin/visas/{id}
------------------------
  Summary
    Revokes a visa. Placeholder: returns a fixed response.

GET /admin/network
------------------
  Summary
    Returns the links the current policy declares between nodes, each marked
    with whether it is actually up.
  Request
    (none)
  Response
    200: NetworkDetails
    403: permission denied
    500: server error
  Notes
    Links are deduplicated by normalized node pair, so each link appears
    exactly once; node_a_addr is whichever endpoint policy iteration
    reached first.
    ctype is UP if a connected node reports the link, DOWN if the policy
    declares it but no node reports it, and INVALID otherwise.
    INVALID entries carry no substrate addresses, link_id, or link_cost.

GET /admin/stats
----------------
  Summary
    Returns service statistics as a map of stat name to value.
  Request
    (none)
  Response
    200: Stats
    403: permission denied
  Notes
    Always includes "uptime" (seconds since service start). Remaining
    entries are the service counters, keyed by counter name. All values
    are stringified.

GET /admin/policies
-------------------
  Summary
    Returns the current policy id. Currently there is only one policy (id 0).
  Request
    (none)
  Response
    200: ListEntry (single object, not an array)
    403: permission denied

  Response

    500: server error

POST /admin/policies
--------------------
  Summary
    Installs a policy bundle and makes it the current policy. Fires a
    PolicyUpdated event on success.
  Request
    Body: PolicyBundle (config_id is ignored; the new policy is always id 0)
  Response
    200: ListEntry (id of installed policy, always 0)
    400: bundle container could not be decoded
    403: permission denied (write permission required)
    500: policy update failed
